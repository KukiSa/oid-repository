# G6 Root Certificate and Cross-EKU Revision — 2026-10-16 R2

The operator explicitly instructed reissuance of the five G6 self-signed root certificates without Authority Key Identifier, retaining Subject Key Identifier, and cross-certificates with specific Extended Key Usage values. Identity uses anyExtendedKeyUsage (2.5.29.37.0); Server uses serverAuth; Mail uses emailProtection; Code uses codeSigning; Timestamp uses timeStamping. The actual root name remains Youngdo G6 Secure Identity EC384 Root.

All five registered public keys and SKIs are unchanged. EJBCA renewed each root using its existing signing-key alias, and retained the previous certificate in history. Cross-certificates retain AKI pointing to Youngdo Root CA and use SHA-384/RSA, pathLen=1, CRL status and issuer-bounded expiry. All ten new certificates were independently checked for signature, public key, subject, SKI, AKI presence/absence and EKU. All six modern and six legacy basic paths and eleven CRLs were verified.

Compatibility result: OpenSSL 4.0.3 does not accept an intermediate CA containing only anyExtendedKeyUsage as satisfying clientAuth. This revision retains the explicitly requested Identity EKU; relying parties requiring OpenSSL client authentication should use the native G6 Identity trust path or require an additional explicitly authorized clientAuth cross-certificate. No claim of universal purpose compatibility is made.

The two G6 TLS leaf profiles now omit SKI while retaining AKI. Other leaf profiles retain their prior SKI settings and six supported CSR key types. Existing leaf certificates are unchanged. Five purpose-specific cross-certificate and end-entity profiles replace the former general-purpose cross template, which remains defined for historical references with issuance disabled.

Public immutable artifacts are under /artifacts/g6/20261016-r2/. EJBCA default and alternate chains reference the new root/cross versions. Current AIA aliases are atomically updated after archiving previous bytes; independent revision URLs avoid reuse of cached prior certificate files. The previous self-signed and unrestricted cross-certificates are retained as valid historical certificates, without a revocation assertion.

The unchanged OID/SPKI/SKI identities and root-group version require no new OID allocation. Ten certificate artifacts are appended to the five existing bindings; prior bindings, certificates, decisions, events and effective policy documents are preserved. The single-operator review exception is recorded in BIND-2026-1016-G6-ROOTS-AND-EKU-R2. Candidate 2026-10-16.1 is archived, and release 2026-10-16.2 remains candidate without a fabricated publication signature. No private key or enrollment secret is published.
